一、事实清单（逐条亲验）
  ①【M40 名义 40s 实跑 16.78s】9 个 M run 的 attack1.log DONE 行全部为
    「t=16.78s subs=420 dels=420 total=840 avg=50/s」（M_cap24_rep1 attack1.log
    尾部亲读；R3D_raw 9 行 done_t=16.78/sent=840 一致）。名义纯轻载 40s
    （churn 50 40 60）实际曝光 16.78s/840 ops=名义时长的 42%——churn 循环
    上限（420 对 sub/del）先行耗尽，速率 avg=50/s 达标但窗长未达。
    → M 臂 0/9 的解读边界：轻载曝光剂量仅为名义 42%，「40s 轻载不发散」
      的原表述过强，应为「16.78s/840 ops 轻载剂量下 0/9 发散」。
  ②【T 臂 4/9 attack2.log 为 0 字节】T_cap24_rep2、T_cap28_rep1、T_cap32_rep1、
    T_cap32_rep2 的 attack2.log stat=0（本轮逐一 stat 亲验）；两个发散 run
    （T_cap24_rep2 pendTO=18,892,358、T_cap28_rep1 pendTO=22,757,833）恰在
    其中；phase2 有正常输出的 5 run（194-197KB）全部 pendTO=0。
    attack2 0 字节的两种解释并列（在盘证据不能判别）：
      (a) 发散 run 的 RIC 在 phase2 启动时已进入不可服务态（SCTP 关联无法
          建立→攻击器无输出）——phase2 失败是发散的**结果**（选择效应，④）；
      (b) 攻击器自身启动失败（独立事件）——无法排除但与「恰好 2 个发散
          run 全在其中、5 个正常 run 全部 healthy」的关联模式相比概率低。
    无论 (a)(b)：T 臂「轻载相 30s 施压」在 4/9 run 未实际发生。
  ③【「全部发散在轻载相显现」名实不符】两个发散 run 的 done_t=10.08/10.02
    （phase1 强攻 10s 后即无第二相贡献），pendTO_mid=0（相位中点 t≈23s 采样
    干净）→ 恶化发生于「强攻结束后的零/低攻击输入窗」（phase2 0 字节=零
    输入），不是注册设计的「轻载施压自持」。10Hz monitor 侧写
    （R3H_zero_input_evolution.txt）：两发散 run 在攻击结束后 CPU 从 0%
    自发跃升至 9-11% 稳态、RSS 从 6MB 单调涨至 21-26MB——零输入下的
    自发恶化直接可视化。
  ④【phase2 启动的选择效应】phase2 能否产生输出与强攻后系统状态相关
    （②(a) 路径），T 2/9 vs M 0/9 的对照混杂「有无强攻」与「phase2 是否
    执行」两因素——Fisher p=0.2353 的两结局规则入册维持，但「T>M=自持
    效应方向支持」的表述需降级为「方向性且混杂未分离」。
  ⑤【offered load 臂内方差未解读——M1 尾句】T 臂 9 run sent=6606-35665
    （5.4×，R3D_raw 亲读）：全速 10s 窗内发送量由 RIC 侧背压/处理状态
    反馈决定（healthy run T_cap28_rep2 sent=35665 vs 发散 run T_cap24_rep2
    sent=9050）——发散 run 发送少的原因是 RIC 早期进入慢服务态（接收
    排空变慢）→ offered load 是系统状态的下游变量，不能作独立剂量解释；
    M 臂 sent 恒 840（循环上限），无此变异。
