〇、处置背景
  双审指出：协议附录 B/RESEARCH_LOG:195/源码注释三处声称「10/10 确定性复现
  +gdb 栈在案」，但全盘无 gdb 会话输出、无复现日志——证据仅存文字层互引。
  本证据包以受控二进制对照独立重做该复现并全程落盘。

一、实验设计（差异唯一化）
  1. /root/autodl-tmp/flexric_r3g = flexric 生产工作树全量副本（含全部已提交
     于工作树的缺陷①-⑥修复与 PATCH7），随后对**唯一一个文件**执行
     git restore：src/lib/e2ap/v2_03/dec/e2ap_msg_dec_asn.c（撤除 PATCH7
     五层守卫中的解码器侧守卫：IE 计数守卫 :473-482 + 终层 type/NULL 守卫
     :2757-2765，恢复 Release NDEBUG 下失效的原 assert 版本）。
  2. 二进制指纹（results/R3G/R3G_binaries.md5）：
     pre-patch（r3g 构建）md5=20a06871ee51de687513b9b3a9dc3aec
     生产修复版            md5=d48e1402ea42c89ed69c360c95fe717a
  3. 环境与 R3B 截断臂同款：L1 全开（FAILCLOSED=1/FULLPOLICY=reject/
     MINLEN=0——关短帧丢弃以隔离守卫唯一差异）+ emu_agent_gnb 在场。
  4. 触发器与 R3B trunc 臂同款：python SCTP SOCK_SEQPACKET 发 2 字节
     {0x00,0x0f}（pc 白名单内+截断 body）→ sleep 0.3s → close 关联，×5 轮。
  5. 捕获方式：gdb --batch launch 模式（容器 ptrace_scope=1 下 attach 不可用，
     launch 为父子关系豁免；R3C 已亲验 attach 路径不可行），
     SIGSEGV 自动停驻并执行 bt 25 + info registers rip。

五、工程注记
  r3g 副本构建的坑：cp -a 全树后 CMakeCache 仍指向原目录源路径，首次
  make 实际编译原目录源（白编）——以 sed 全量改写 build 树内路径+touch
  源文件后重编解决（progress.log 可见两轮构建）。此坑与 R3B 的
  「progress.log 自报时间与 Birth 矛盾」（m6）同族：构建/日志系统的
  自报信息不可作为物理证据，指纹（md5）才是。
